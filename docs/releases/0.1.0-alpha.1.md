# Draft 0.1.0-alpha.1 qualification

Status: local macOS qualification completed; hosted publication failed and no
GitHub release was created.

This record covers source commit
`b89d733bece555da28d0db9664103820e97a92b2`. The record itself is a later
documentation-only change: rebuilding it naturally reports the later Git
identity in `--version`, but it changes no compiler implementation.

## Local native qualification

The candidate was configured in a dedicated release build directory on
2026-07-27 with:

- macOS 26.5.2 (`25F84`) on AArch64;
- Apple Clang 21.0.0 as the C++20 bootstrap compiler;
- LLVM 22.1.8 from the explicit Homebrew LLVM 22 CMake package;
- CMake 4.3.0;
- `CMAKE_BUILD_TYPE=Release`;
- warnings as errors; and
- bootstrap sanitizers disabled.

Both `draftc --version` and `draftide --version` reported release
`0.1.0-alpha.1`, the exact qualified source commit, LLVM 22.1.8, the same
embedded core identity, and all four implemented target selectors. The complete
CTest run passed 98 of 98 tests in 22.65 seconds. That run included native
determinism and backend parity, C client integration, classified examples,
Draft tests and benchmarks, provider-free agent fixtures, DraftIDE/compiler-
service integration, and the isolated installed-distribution smoke.

## Archive qualification

CPack produced
`draft-0.1.0-alpha.1-aarch64-macos.tar.xz` from the same install manifest. The
exact local artifact was 63,341,984 bytes with SHA-256:

```text
ac044a6c932eff610b946c563f9c53854516c90ac44b8092f45af57fc2ea8cdc
```

The archive expanded to approximately 338 MiB. Its private Clang resource tree
contained compiler-rt libraries but no unused general-purpose C builtin-header
set. After extraction into a new directory:

- `draftc` and `draftide` both reported `toolchain: bundled`;
- `draftc` checked, built, and launched the installed `examples/hello` package;
- DraftIDE loaded its installed sibling compiler service and completed its
  noninteractive smoke;
- neither binary needed a checkout, Homebrew LLVM path, or loader environment
  override; and
- strict recursive code-signature verification passed for both macOS
  executables after loader-path fixup and ad-hoc signing.

## Hosted publication attempt

The immutable `v0.1.0-alpha.1` tag names
`5b2f9d924c8646e7e6ec66dbac12cbd803426c49`. Its ordinary CI run
[30317709514](https://github.com/miguelbranco80/draft/actions/runs/30317709514)
passed the macOS ARM64, Linux ARM64, Linux x86-64 ASan/UBSan, and Windows
x86-64 gates.

The tag-triggered release run
[30318845096](https://github.com/miguelbranco80/draft/actions/runs/30318845096)
did not publish:

- macOS built, tested, packaged, extracted, and exercised its archive;
- both optimized GCC/Linux builds stopped at a warning-as-error in the
  compile-time slice-bound representation;
- Windows passed native and installed-distribution qualification, built its
  archive, and then rejected the extracted archive because the workflow passed
  its expected version incorrectly; and
- the publisher was skipped because all four native archives had not qualified.

The two release-only defects were corrected after the immutable tag. This
record deliberately does not describe `alpha.1` as a GitHub release and does
not reuse or move the failed tag.
